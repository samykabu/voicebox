## [Unreleased] - 2026-09-23

### Added

- **VoxCPM2 as the ninth TTS engine** (`backend/backends/voxcpm_backend.py`, engine id `voxcpm`, model `openbmb/VoxCPM2`). Apache-2.0, commercial use allowed, 48 kHz output read from the model rather than hardcoded. `voxcpm==2.0.3` is pinned and installed with `--no-deps` plus a minimal set of transitive packages found by the dependency probe (FR-001, FR-005, FR-006).
- **30 languages** declared by the engine, Arabic included, in model-card order. Seven of them (Burmese, Indonesian, Khmer, Lao, Tagalog, Thai, Vietnamese) are new to the product and offered only by VoxCPM2 for now (FR-007).
- **Pronunciation dictionary support.** It runs on the input text before generation, and upstream normalisation stays off (`normalize=False`) so it cannot undo the Arabic diacritics handling from PR #11 (FR-008).
- **Voice cloning** from existing profiles, including multi-clip profiles combined through the shared helper at 24000 Hz. Prepared references are cached under a `voxcpm_` prefix so another engine never picks them up. `voxcpm` is in `CLONING_ENGINES` (FR-011 to FR-014).
- **Seeded, repeatable generation.** The seed is applied with `manual_seed` right before the vendor call, because voxcpm 2.0.3 takes no seed argument (FR-009).
- **Voice design from a written description** (FR-015, FR-015a):
  - a new "Describe a voice" profile source that creates a `designed` profile from `design_prompt` alone;
  - a separate, labelled "Voice description" input in the generate box, shown only for engines that declare voice design, sent as `voice_description` and never as `instruct`;
  - precedence: a recording on the profile wins, then a one-off description, then the profile's own description. The generate box says so when a recording overrides the description;
  - long designed text keeps one speaker: chunk 0 is generated from the description, saved as an untagged temporary WAV, and the later chunks clone it. The temp file is deleted in a `finally` block, including on cancel.
- **Engine capability channel**: `GET /models/engines` returns, per engine, availability with a reason or warning, supported and detected accelerators, languages, cloning and voice-design support, download confirmation flag, advanced settings, size, licence and commercial-use status. The app reads it through a new `useEngineCapabilities` hook (FR-002, FR-004, FR-024).
- **Advanced generation settings** for VoxCPM2: Guidance (`cfg_value`, default 2.0, range 1.0 to 3.0) and Quality steps (`inference_timesteps`, default 10, range 4 to 30), rendered from the declaration with the defaults preselected (FR-010).
- **Download confirmation** for VoxCPM2 only, showing the measured 4961 MB size. It fails closed: if capabilities have not loaded, the app still asks (FR-018).
- **Memory warning** before the download when detected memory is under 6144 MB. It is advisory and never blocks (C1Q4).
- **Processor fallback warning** on Intel XPU and DirectML machines, where VoxCPM2 runs on the CPU (FR-023).
- **Responsible-use notice** in the profile dialog for all three sources (clone, built-in, described), with a link to the Responsible Use guidance (FR-025).
- **AI-generated disclosure** in every generated WAV: `ICMT = "AI-generated by Voicebox"` and `ISFT = "Voicebox"` in the RIFF INFO chunk. Covers saved generations and processed versions (including `/speak` and MCP speak), `/generate/stream` and the effects preview. The user's own audio (reference samples, the combined reference, the transcription re-encode) is never tagged (FR-026).
- **New tests**, among them `test_voxcpm_backend.py`, `test_engine_capabilities.py`, `test_cpu_fallback.py`, `test_engine_patterns.py`, `test_language_patterns.py`, `test_generation_advanced_settings.py`, `test_audio_disclosure.py`, `test_profile_export_provenance.py`, `test_engine_load_failure.py` and the review-fix suites (`test_voxcpm_review.py`, `test_review_*.py`). A VoxCPM2 case was added to `test_all_models_e2e.py`.

### Changed

- `ModelConfig` gains five fields that default to today's behaviour: `accelerators`, `supports_voice_design`, `requires_download_confirmation`, `min_memory_mb` and `advanced_settings`.
- `GenerationRequest` gains two optional fields, `voice_description` (max 500 characters) and `advanced_settings`. Unknown or out-of-range settings return 422. When the request has no engine, `/generate` and `/generate/stream` run the same check after resolving the profile's default engine.
- Generating with an engine this machine cannot run returns 400 with the reason. Only an engine that declares hardware without `cpu` can hit this, and none does today.
- The four engine regex patterns in `backend/models.py` accept `voxcpm`, and the language patterns accept the new codes.
- New nullable column `generations.voice_description`, added through the existing `_add_column` migration. Retry and regenerate replay the stored description.
- `utils/chunked_tts.py` looks up two optional hooks, `continuation_voice_prompt` and `release_continuation_voice_prompt`. Only VoxCPM2 defines them.
- Profile export manifest moves to 1.1 and carries `voice_type`, `preset_engine`, `preset_voice_id`, `design_prompt` and `default_engine`. Designed and preset profiles export without samples. 1.0 archives still import, as cloned profiles.
- Generation export manifest moves to 1.1 and carries `voice_description`, `engine` and `model_size`. Import checks the engine and size against the registry and validates the description with the API's rules. Blank text is rejected before any file is copied, and a failed commit removes the copied audio.
- Install and packaging: `justfile` (both platform paths), `backend/requirements.txt`, `backend/build_binary.py` (hidden imports and data), `Dockerfile`, and the install steps of the three build jobs in `.github/workflows/release.yml`. Runners, triggers and job structure are unchanged.
- The generated TypeScript client was regenerated with `bun run generate:api`. Biome now skips the generated client.
- Docs: `tts-engines.mdx`, `model-management.mdx`, `tts-generation.mdx`, `voice-profiles.mdx`, the overview pages on profiles, generation, cloning and GPU acceleration, `backend/README.md` and the root `CHANGELOG.md`.

### Architecture & boundaries

- The change is additive. The `TTSBackend` protocol is unchanged; VoxCPM2's extra `options` keyword is injected by `backend_with_generation_options` only for engines that declare advanced settings.
- The capability channel is used by the app for VoxCPM2 only. The other engines keep their hand-maintained lists in the app, as the spec requires, though the endpoint already reports them.
- There is no `if engine === 'voxcpm'` capability branching in the app. Conditions read the declared data.
- Heavy imports stay lazy. The capability endpoint never loads a model or imports torch at module scope.
- A cached model loads with the network off: `force_offline_if_cached` wraps the load, and `load_denoiser=False` keeps the vendor from contacting ModelScope.
- Model load and inference each take a lock, as in the Chatterbox and F5-TTS backends. VoxCPM2 declares `retries_runaway=False` because the vendor already retries.

### Migration

- One nullable column, `generations.voice_description`. Existing rows read as null and replay as before.
- Export manifests 1.0 import unchanged. No user action is needed.

### Scope (not in this phase)

- Streaming generation (`generate_streaming`).
- VoxCPM2's `reference_wav_path` cloning mode, the denoiser, and other model sizes (VoxCPM 1.5, 0.5B).
- Moving the other engines onto the capability channel.
- Saving advanced settings with a generation. Retry, regenerate and `/speak` use the defaults.
